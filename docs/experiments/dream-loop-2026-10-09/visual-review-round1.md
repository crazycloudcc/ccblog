## 全部实质性可修复问题

### 1. P0：首屏缺少完整核心等式

- 证据：步骤2的画面中，进度条约在 y=624，结论栏从 y=644 开始；主内容可见区到约 y=689 为止，只能看到“去掉相同部分，余下面积相等”标题，不能看到 25=9+16，更看不到清晰完整的 a²+b²=c²。
- 影响：读者看见两组面积，却要滚动后才获得本课的关键联系。结论本应是双图的即时视觉落点。
- 源码依据：等式位于 `PythagoreanExperience.tsx` 的 conclusion 标题之后（首版第47行）；`TerminalPageEntry.tsx` 第39–44行还为该课追加约52px高的 cd 路径行。终端外框采用固定视口高度、内部滚动，下沿状态栏占有固定空间。
- 修复：回收该课重复的 cd 行；把清晰的符号等式和当前数值等式前置到结论首行，紧接舞台或与进度控制组成紧凑布局。说明段落可以下移，但核心公式应真实在首屏内。
- 复验：相同1180×757、100%缩放、页首位置，标题、步骤、a/b、两幅完整图形、核心公式与数值等式无需滚动即可见。不能通过进一步缩小图形来挤入公式。

### 2. P1：几何实际尺寸太小，面板留白没有服务教学

- 证据：步骤2中每个面板约426px宽，外框正方形仅约214px宽。左右图的主面积与三角形虽然正确可辨，但视觉重量明显小于目标中的大型几何舞台。
- 源码依据：`.diagram` 限制 `max-height:275px`，SVG 为 `viewBox="0 0 370 362"`，真正外框只有280×280；按高度约束计算，外框约为 `275×280/362≈213px`。这是图形尺寸不足的直接原因，不是需要再加卡片内容。
- 修复：同时紧缩 SVG 安全留白、重分配页首垂直空间，并适量提高可用图形高度。保留尺寸线与外引线标签所需空间。不要仅增加容器高度而让公式继续落到下屏。
- 复验：在同一视口下，建议外框达到约250–280px，且两图尺寸保持一致、四角与尺寸标注完整。最终以实际截图教学可读性为准，不机械复制生成图比例。

### 3. P1：图内边标、编号和极小面积标签读起来吃力

- 证据：步骤2的三角形编号和 a/b 边标偏小；步骤3右上方的 a²=1 实际挤在约24px宽的小正方形内，很难作为教学主信息阅读。
- 源码依据：编号与小面积标签为12个SVG单位，受首版约0.76缩放影响，实际接近9px。编号使用3个SVG单位的浅色描边，在小字上明显侵蚀字形。
- 修复：提高实际呈现字号；编号可用深色字或清晰小标记承载，减弱小字浅色描边。极端比例时将面积文字用短引线移到图形外，明确指回对应正方形，不能把小正方形放大或改变真实面积比。
- 复验：a=1,b=8 以及反向 a=8,b=1 均检查；面积标注、编号、尺寸线不互相遮挡，正方形保持比例。普通边标/编号以实际至少约12px为可读性目标。

### 4. P1：移动中的证明限制提示过小

- 证据：步骤4已清楚出现三角形重叠，且右图底部有“平移中 · 允许重叠，终点再比较剩余面积”，但实际约9px、贴近面板底部。结论中的完整解释仍在首屏以下。
- 影响：这是避免把中途空白误当面积证明的关键限制，不宜作为难读的脚注。左右对照本身很好，应保留。
- 修复：将该句作为清晰的舞台图注或状态行，至少约12px实际字号。移动时保留“只移动、不变形”和“终点再比较”的可见提示，优先于装饰性元数据。
- 复验：进度50%时，同屏清楚看到重叠允许发生、此时不比较空白剩余面积的说明；到0%与100%时不遗留过时的中途说明。

### 5. P2：a/b 滑块的范围尾标换行

- 证据：步骤2、3、4中，两个滑块右端均显示两行“1–”与“8”。
- 源码依据：滑块 `width:100%`，尾标没有不换行或不收缩约束；输入与尾标竞争同一行空间。
- 修复：给范围尾标 `white-space:nowrap` 和不可收缩宽度；让输入使用可收缩的弹性剩余宽度。保留当前 a/b 数值在最左侧的清晰展示。
- 复验：同一1180px截图中两个“1–8”都在一行，并在后续实际窄屏验证中检查不会产生横向溢出。
